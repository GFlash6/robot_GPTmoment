# 共享动作的增量事件读取

`task.events-page` 通过已有 HTTP/CLI 动作入口读取实际任务事件，使用 `tasks.read` 权限并在每次调用时复核机器人范围。该动作不会启动模型、推进任务或重新派发技能；应用层仍会记录本次读取的审计信息。既有 `task.events` 和只读观察 API 保持兼容。

输入为 `task_id`，可选 `after_seq`（默认 0）、`limit`（默认 100，范围 1–500）和 `through_seq`。响应包含 `task_id`、`events`、`next_seq`、`through_seq`、`has_more`。事件字段保留真实 seq、ts、task、type，并将 data 解析为 JSON。

推荐读取流程：

1. 首次从 after_seq=0 请求；服务端返回该任务当时的最大事件序号 through_seq。
2. 将 next_seq 作为下一页 after_seq，并固定使用本轮 through_seq，直到 has_more=false。
3. 新一轮增量读取保留最后的 next_seq，省略 through_seq，获取新的上界。
4. 只有成功处理本页事件后才保存游标。网络中断后可重复请求同一页，客户端按 task_id/seq 去重；重连不会触发技能重试。

服务重启不会重置账本游标。非零 after_seq 和 through_seq 必须是该任务真实存在的事件序号，拒绝跨任务、未来游标及反向范围。参数错误沿用应用 HTTP 400 INVALID_ARGUMENT；机器人权限不足返回 403。客户端不能通过保存游标绕过后来改变的权限。

序号属于全局账本，其他任务插入事件会使单个任务的序号不连续。因此不使用 seq+1 判断漏读。本接口按任务索引和固定上界查询；不提供任意数据库历史删改的检测或跨账本迁移游标。手工删除中间事件无法仅靠序号间隔可靠识别。每页限制的是事件条数，不是响应总字节数。

## 验证

`tests/test_event_pages.py` 使用实际文件任务、独立 worker 和带真实鉴权的 HTTP 服务，验证固定上界、逐页重新连接、服务重启续读、重复读取、不同机器人事件交错及拒绝路径。未创建伪造事件或模型响应。

`tests/test_multifile_live.py` 在环境真实模型生成并实际执行七节点任务后，逐页读取全部事件，与完整账本逐条比较，检查七个真实 execution_result，并确认读取没有增加模型记录或改变任务。该链路同时核验实际文件哈希。

实际验收证据见 [event-pages-live.json](validation/event-pages-live.json)。

## 工作台接入

应用动作目录包含 `task.events-page` 且操作者连接成功后，工作台显示“任务事件记录”。列表只读取有权限的任务，可按任务切换；当前提交或从任务流程选中的任务可作为初始选择。每次最多读取 50 条事件，有后续页时等待操作者点击“加载后续事件”；本轮读完后每 2.5 秒查询新增记录。

界面检查任务身份、递增序号、页边界和游标推进，校验或网络错误时保留上次记录并显示错误。切换任务取消旧请求结果的应用，改变凭据会卸载事件区域。查看事件证据只展开真实 JSON，不调用模型或控制任务。任务列表可单独重新读取。

`ui/scripts/test-events-ui.mjs` 复制既有真实模型任务账本用于浏览器只读验证，再通过实际暂停/恢复及文件执行生成 69 条事件测试分页；没有网络拦截、虚构响应或新模型调用。它实际停止并重启应用服务，验证断连保留、重连去重、任务切换和凭据隔离，并截图桌面和手机布局。该测试不证明浏览器重新生成了模型计划；模型调用与实际执行来源是关联的原始验收记录。
