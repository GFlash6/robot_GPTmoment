# 多文件任务与集合核验

内置 `asset.verify-set` 为一组资产提供统一最终核验。输入 `items` 包含 1–100 个 `{asset_id, sha256}`，其中哈希是调用方明确给定的预期值。技能拒绝重复资产 ID，逐项读取真实资产字节，验证目录完整性、机器人范围及预期 SHA-256；全部通过后返回 `verified=true`、`count`、每项实际哈希和大小，以及逐资产证据。任意一项失败，整个执行失败，不返回部分成功集合。

技能和其他本地只读核验一样保存 execution_id 对应的持久结果。查询同一次执行返回该次历史结果；需要核验后来变化的字节时应创建新的执行。集合核验并不提供并发写入下的原子文件系统快照。

## 实际模型评测

`tests/test_multifile_live.py` 使用环境配置的真实模型，从实际项目文档构造三项源文件、目标路径和预期哈希清单。模型通过应用动作生成七节点任务：三个复制、三个归档、一个集合核验。评测独立检查：

- 复制路径与任务清单一致；归档读取复制步骤真实返回的 path。
- 最终核验直接依赖全部归档，asset_id 引用对应输出，预期哈希使用清单值。
- 保存真实模型消息、原始响应、上下文包和任务计划。
- 独立 worker 实际执行，七个步骤全部成功后再次读取三个复制文件和三个归档资产核验字节。

运行命令：

```bash
RUN_LIVE_MODEL_TESTS=1 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest tests/test_multifile_live.py -q -s
```

每次运行使用新的目录，保存成功或失败报告，不覆盖既有证据。测试提供明确的任务与依赖要求，衡量受约束的多文件计划与执行正确性，不据单次成功宣称开放目标推理质量、统计成功率或真机能力。运行成本和延迟保留在实际模型账本及报告中。

## 拒绝路径

`tests/test_asset_verify_set.py` 操作真实项目文件和资产，覆盖预期哈希错误、存储字节被实际改写、重复 ID 和跨机器人范围；这些均须失败，且查询保留同一次执行结果。测试没有替代模型、虚构传感器或伪造成功响应。

实际结果：41 项回归与 1 项真实模型任务通过；两次模型调用、七个成功节点、三个最终核验资产。完整证据见 [multifile-live.json](validation/multifile-live.json)。
