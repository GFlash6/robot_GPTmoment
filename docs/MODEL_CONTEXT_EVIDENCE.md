# 模型调用的上下文证据

模型请求原文是确认实际输入的依据。ContextBundle 保存构造前的片段及来源，ContextManifest 保存这次请求实际纳入、预算丢弃和来源诊断；两者不能代替实际模型响应或执行证据。

## 已接通的调用

| 调用 | Bundle | Manifest | 限制 |
|---|---|---|---|
| 规划/重规划的 ContextRequest 路径 | 完整 v1 包及哈希 | 来源、Provider、预算 | 旧 CLI 任意 context 路径另行兼容，不补造 Bundle |
| goal_analysis / goal_clarification | 完整 v1 包及哈希 | 各次调用独立预算与来源清单 | 会话路径保留预检 Bundle；直接调用没有 Provider 时 diagnostics 为空 |
| task_explanation | 完整 v1 包及哈希 | 来源、Provider、预算 | 解释历史任务状态，不构成新的环境观测或任务成功 |
| 自动化事件诊断 | 完整 v1 包及哈希 | 来源、证据引用、预算 | 来源为绑定的历史失败事件，不声明当前任务版本；不补造 Provider 诊断 |
| 会话/恢复摘要 | 每个实际分块的完整 v1 包及哈希 | 原文范围、证据引用、预算 | 恢复摘要另绑定原规划快照与任务版本；原始覆盖范围及并发检查继续生效 |

## 目标分析与澄清

`fit_session` 返回有效会话和它实际预检的完整 ContextBundle。自动摘要发生后，返回摘要生效后的包，不再仅返回 fragments 并丢失 diagnostics。`plan.propose` 保持既有规划包构造路径；`goal.analyze` 把预检包传给 GoalAnalyzer。

GoalAnalyzer 检查目标原文与包一致，严格编码/读取包后准备实际请求。准备参数先经过与账本相同的 JSON 规范化，再生成首次请求，避免实际分析响应中嵌套对象的键顺序在持久化后改变提示文本。目标解释的分析响应经语义契约校验后，才可能触发独立澄清调用；澄清调用使用相同输入上下文和实际分析结果，每次仍单独计算预算与保存 Manifest。

在网络调用前，一个事务保存：

- `context_bundles[model_record_id]`：完整包；模型记录保存其规范哈希。
- `context_manifests[model_record_id]`：本次分配及来源。
- `model_responses[model_record_id]`：实际 messages、response_format、模型名、准备方法与参数，以及上述引用。

网络调用在事务之外。真实响应先保存原文，再做 Goal/问题内容校验；无效模型输出保留在 rejected 记录中。准备或预算失败可能只有 rejected 模型记录，不伪造已发送请求。历史记录不做回填。

`context_evidence.context_manifest` 是目标分析、失败解释、事件诊断和历史摘要共用的纯构造函数，不执行网络请求或修改存储。Provider 为空和片段被丢弃是不同情况：前者没有返回适用片段，后者有实际预算丢弃原因。

## 会话与恢复摘要

每个分块用 `history_summary` phase 标识，`summary-source` 是必须纳入的 data 权限片段，保存原始目标和原文字符范围。`kind=memory` 表示供模型参考的数据，不将 assistant 原文提升为观察事实，也不表示已经写入长期记忆。片段 metadata 和 Manifest 同时记录 source_parts 的 turn ID、Unicode 字符起止位置和内容哈希。

分块预检与发送都使用相同片段、相同问题和渲染规则；单条消息过长时仍按实际预算二分切分，不截断未记录的文本。严格编解码后的 Bundle 用于实际发送。每块的包、Manifest、准备参数、实际 messages、response_format 和 temperature=0 在一个事务中保存，然后才发出网络请求。来源构造没有调用 Provider，diagnostics 为空。

普通摘要绑定实际 session ID、robot ID，模型记录另存会话 revision。恢复摘要继承被接受的 ContextRequest 的 context_snapshot_id、task_id、revision/generation；不会改读操作者之后编辑的当前会话。请求 ID 对每块唯一，原快照与新的派生快照保持区分。

已有摘要原文覆盖检查、固定消息保护和每块前后的恢复 guard 保持生效。并发编辑或取消后，实际返回的部分摘要仍可审计，但不得将它绑定到更新后的会话或继续生成恢复计划。新 phase 使用 Bundle v1 的既有字段格式，不认识该 phase 的旧读取器会拒绝；旧摘要请求不回填为新格式。

## 重建与验收边界

只读观察 API 提供 `GET /api/v1/models/{id}/context`，在一个读事务中展开实际关联的 Bundle 和 Manifest，并报告包哈希与引用一致性。它不导入 Runtime 或模型调用层，不触发模型、任务执行或历史补写。检查范围与返回状态见 [观察 API](UI_API.md)；此接口不等同于下述实际请求重建。

模型记录页面下方的“本次调用的上下文”区域已接入该接口。选择已有模型记录后，可以查看关联状态、输入估算/上限/输出预留、来源片段及预算丢弃原因；原文、元数据、Provider 诊断和请求身份通过原生展开控件查看。历史无包记录明确显示不可用，损坏或关联异常显示问题列表。

切换记录清除上一条的数据，异步旧请求不会覆盖新选择；断连保留本次选择的上次成功结果并提示过期，重连后继续只读刷新。浏览器不会从该区域调用模型、重跑任务或补写缺失证据。浏览器验证见 [context-browser-live.json](validation/context-browser-live.json)，使用既有真实模型账本的副本，新增模型调用为 0。

使用持久包解码得到 fragments，使用模型记录中的 preparation 方法和参数，经当前 ModelCaller 重新准备，再比较实际 messages、response_format 与 allocation。这里验证的是当前提示实现和模型配置下的输入可重建，不代表跨提示版本自动兼容；真正的历史请求原文始终保留。

会话目标分析保留初始原文与后续澄清；模型解释不会反向覆盖原始消息。有效来源可能在后续失效，已有记录仍用于审计，不能据此重新授予派发权限。

验证要求：使用环境真实服务和模型；检查响应内容、原始响应标识、来源清单和实际请求重建。明确文件目标还需由独立 worker 执行并核验实际字节；失败解释必须保留真实失败状态。没有机器人证据时，不声明 WorldState 或物理动作闭环完成。


## 实际验证记录

见 [目标分析与澄清真实验收](validation/goal-context-live.json)。初次组合运行 2 项通过、1 项失败；失败来自实际澄清提示的 JSON 键顺序变化，修复后对应完整真实模型路径重验通过。普通与自动摘要路径不重复调用模型，使用最终规范化参数对保存的实际请求、来源包和预算进行只读重建复核。三条通过路径共 13 条真实响应，文件任务两项实际成功、解释任务保留真实失败。另有 23 项实际文件/账本/HTTP 回归通过。所有结论限定当前提示与模型配置，不宣称完整框架验收完成。


自动诊断增量见 [自动诊断上下文实际验证](validation/automation-context-live.json)：4 项专项通过，覆盖实际失败诊断、范围/完整性、SIGKILL、SIGINT 和显式重新诊断；5 条已验证真实响应、2 条没有响应证据的中断请求，全部 7 份准备输入可准确重建。未将中断请求算作已取得模型响应；原始不确定记录及事件快照保留。


会话/恢复摘要增量见 [摘要上下文实际验证](validation/summary-context-live.json)：自动摘要后实际文件执行、并发编辑拒绝旧摘要、恢复摘要后实际文件执行、摘要期间取消四条路径通过。8 个摘要包的原文字符范围、实际消息、response_format、temperature=0 及 allocation 均经核对；通过路径共 15 条真实响应。两次前置失败与对应重验记录保留，未以替代响应或放宽生产校验取得通过。


## 跨调用差异

观察 API 已提供明确方向的 `context-diff?against=...` 查询；对比请求身份、语义目标、片段来源和内容哈希、预算及 Provider 诊断。双方在同一读快照读取，缺失/损坏证据不返回“无变化”。来源哈希与页面脱敏后的内容哈希范围不同，比较不证明调用父子关系或设备事实。完整接口契约见 [UI_API](UI_API.md)。

[差异验证记录](validation/context-diff-live.json) 使用既有真实模型的规划、分析、摘要与恢复记录，检查 16 组有方向的比较、实际来源/预算/内容变化、并发提交隔离、复制账本损坏及旧记录缺失；8 项专项与观察回归通过，新增模型调用为 0。世界观测有效性和真机闭环仍待完成；浏览器双记录交互见下述增量。


## 浏览器中的双记录比较

模型记录列表与响应检查器下方新增“上下文对比”，位于既有单记录上下文区域之前。选择模型记录后可使用“使用当前记录为基准”，随后选择另一记录；也可在带标签的输入框粘贴跨页基准 ID，点击“应用基准”后才改变实际查询。基准固定期间切换当前记录会按新方向只读查询；“清除基准”清除比较。

界面显示双方完整 ID、基准到当前的方向、来源/范围差异、预算变化以及新增、移除和变化的片段。预算使用成对值，片段来源和字段变化通过原生展开控件查看。显示内容哈希与存储 Bundle 哈希属于不同范围；这不是模型正确性或调用继承关系的证明。原始当前片段继续在下方单记录区域查看。

同一组合断连时保留上次成功结果并提示可能过期；任一 ID 切换立即清除不相关结果，重连后刷新。历史缺失、哈希异常或无法比较的结构显示“无法比较上下文证据”；不存在的记录显示实际 API 错误，不把这些状态显示为零差异。

[浏览器证据](validation/context-diff-browser-live.json) 包含 5 条实际历史模型记录，验证键盘固定/展开、真实规划与恢复来源和预算变化、正反向与自身比较、未应用输入隔离、旧记录和缺失记录、实际服务断连/重启、复制账本损坏及恢复、清除基准和桌面/手机布局。无浏览器写操作、新模型调用、mock 或仿真；最终账本内容哈希与初始值一致。
