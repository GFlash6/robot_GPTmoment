# 第一版架构与执行契约

用户已批准按开源调研路线开始实现。工作范围是当前 robot_agent_framework 子目录；既有 ROS2 驱动与导航不变。

本文保存第一版已经采用的执行契约。完整目标分层、组件接口、状态机、部署视图和 G1 任务案例见 [详细架构](DETAILED_ARCHITECTURE.md)；实际完成状态仍以 [工程状态](PROJECT_STATUS.md) 为准。

## 组件与状态所有权

DBOS 2.31.0 承担持久工作流恢复、步骤日志与等待；本地开发采用其 SQLite 后端。机器人任务账本使用独立 SQLite 事务记录计划版本、步骤、执行身份与资源控制权，不自行替代 DBOS 的工作流历史。py_trees 2.5.0 的序列/选择器表达技能结果校验链。MCAP 1.4.0 负责原始观测记录格式。jsonschema 校验模型计划和技能输入/输出；httpx 执行实际 HTTP 请求。

一个主工作进程由文件锁限制；DBOS 内部各任务工作流可以并发，但每次机器人控制账本变更受事务和进程内锁保护。资源同时支持容量和机器人命名空间；分配原子化。结果未知时锁不自动到期释放。多机器人预留 robot_id，但本版未验证分布式调度。

## 生命周期

任务：queued/running/pausing/paused/canceling/canceled/failed/succeeded/unknown/replanning。步骤：pending/running/unknown/failed/succeeded/canceled。一次执行的 ID 在派发前持久化。恢复看到已有执行只能 query 原 ID，不能重发；远端不存在记录也按 unknown 处理。

计划为依赖 DAG，至少一个最终验证节点；所有必需步骤均通向最终验证。输入可以引用成功依赖的真实 output。每步 fallback 列表和 retry 次数有界；失败替代结果仍按原步骤后置条件检查。只有终态且 quiescent 为真才释放资源，失败也必须满足该条件。任务取消/暂停先请求活动技能取消，再等待终态；未知保持占用。恢复会重新执行被取消的步骤，因此要求注册技能明确 replay_safe；不安全的步骤拒绝自动恢复。

优先级用于尚未获得控制权的任务选择；显式抢占请求低优先级任务暂停，不把优先级更高等同立即获得物理控制权。资源已占用时等待。重规划仅在无活动/未知技能时修订计划；保留原计划与事件。

## 外部调用

HTTP 技能协议：PUT /executions/{id} 以固定 ID 提交，GET 查询，POST /executions/{id}/cancel 请求停止。注册配置固定端点、参数/结果 schema、资源、取消和重入能力。模型不能构造任意端点或更改技能权限。响应必须含 matching execution_id、status、quiescent、output、evidence。成功需结果 schema、声明式后置条件和可追溯非空证据通过；HTTP 2xx 或 success 字符串不够。

模型通过显式配置的 Chat Completions 兼容端点请求结构化 DAG；原始响应持久保存，校验空内容、终止原因、JSON、计划契约。没有配置立即报错，不生成默认计划。失败后可用实际模型响应重新规划，但只能在前一执行已停止且任务预算允许时接受。

本地内置文件摄取/完整性校验技能实际读取文件与资产，作为框架自用数据操作。它们的测试不冒充机器人验收。

## 数据与记忆

MCAP 记录真实消息字节、schema、channel、采集与接收时间。资产目录保存内容哈希、原始格式、robot_id、frame、clock、标定、地图版本、父资产。资产读取核验哈希；语义条目必须引用存在且有效的资产，记录有效时间与属性，提供结构化和文本索引。地图、观测和模型摘要分开。DimOS 的整体 memory 接入尚未验证，因此本版只采用小型资产/证据目录，避免声称已集成 DimOS。

## 验收

软件检查覆盖真实文件入库/损坏检测、MCAP 读写、DAG 拒绝、多资源竞争、失败 fallback、未知结果锁保留、暂停/恢复、持久执行重启。模型和机器人接口必须另用真实服务验收；缺配置如实标记未验证。不得提供伪模型或伪机器人实现。

## 实际集成补充

提供 loopback HTTP 数据技能服务和可取消的分块文件复制；它们用于真实数据处理和协议验证。自动重规划有显式次数预算、注册 verifier 和 generation 检查；迟到响应不能覆写新计划或取消。rosbag2 录制适配使用本机已安装的 sqlite3 插件，MCAP 插件缺失时明确拒绝；Python MCAP 记录独立可用。
