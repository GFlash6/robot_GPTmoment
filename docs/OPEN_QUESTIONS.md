# 机器人 Agent 框架：模块细节与证据台账

本文件持续维护需求、当前决策、尚缺信息和验证边界。未决问题不由虚构数据或默认成功填补。

状态同步：2026-09-22。软件文件任务、应用控制和模型恢复已完成下述限定范围的验收；整体仍进行中。各模块和细项的已完成、进行中与未完成状态统一维护在 [工程状态](PROJECT_STATUS.md)。本文件继续保存待决问题、实现边界和关闭所需证据。

## 已确认

- 单机器人多任务、多资源；机器人 ID 与资源命名空间预留多机器人接入。
- 长程任务分解、动态子任务、原子技能、fallback、打断和恢复是核心；探索只是检验场景。
- 大规模修改之前广泛调研并尽量复用开源资源；使用 Momo 管理项目。

用户已确认 `robot_agent_framework/` 为正式单一项目，Momo 已建立并注册，已进入具体实现。
- AI 结果必须来自真实服务响应且通过内容校验；技能必须返回实际结果并通过技能后置条件。
- 不生成模拟机器人、伪传感器、假模型回答或占位成功。

## 验证规则

真实文件、SQLite 事务、实际本地技能可用于内核测试，但不代表机器人端到端验证。
AI、ROS2、机器人执行和硬件急停未完成真实联调前，必须明确标记未验证。
测试输入用于验证拒绝非法数据，不得作为生产观测或实验成功证据。

## 当前仍未验证的关键模块

- 通用长程计划质量与物理任务闭环尚未证明；文件任务、多文件执行、失败自动重规划及冻结完成契约恢复已有真实模型和实际字节证据，见 validation/multifile-live.json、validation/replanning-context-live.json、validation/completion-recovery-live.json。
- 机器人停止证据适配、不可重入动作补偿、硬件急停与控制端旧执行者隔离；现有 HTTP 数据技能不代表这些已完成。
- RGB/深度/点云/各地图的实际数据吞吐、标定时间同步和地图失效传播；目录契约和记录管道已有实现，现场数据尚缺。
- DimOS memory、空间场景图、向量检索、自动实体合并尚未集成，属于后续验证项。
- 默认单工作进程；py_trees 当前用于结果条件链，并非已经实现完整可视化行为树编辑器。

## UI 后续模块问题

只读 UI 已实现，验证见 [UI_VALIDATION.md](UI_VALIDATION.md)。以下需要继续完善：

- 任务控制与编辑：独立共享动作 API、权限、幂等命令及工作台控制已实现；现场设备状态与停止证据仍需接入。动作发现已有版本、哈希和副作用声明，详见 APPLICATION_LAYER.md。
- 运行健康：worker 和机器人心跳由谁提供，如何区分在线、失联与停止确认；当前只显示 API 连接和未观测的运行端状态。
- 数据预览：RGB/深度、点云和多类地图的实际解码器、坐标标定、版本切换、流量限制；当前只展示登记元数据及来源关系。
- 大规模查询：任务执行与历史详情分页、SQLite JSON 查询索引、分页一致性和事件推送；当前任务详情读取全部尝试，事件画面保留最近读取的 1000 条。
- 历史契约（已完成，2026-09-07）：内核修订快照保存当时的 plan、steps、catalog、revision、generation 和时间；UI 显示对应版本契约，旧记录缺字段时明确标记不可用。
- 部署访问：跨机器只读权限、认证代理、任意模型原文的敏感内容策略；当前观察服务仅 loopback。
