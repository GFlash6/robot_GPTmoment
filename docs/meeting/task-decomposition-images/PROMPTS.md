## 03 分解机制与输出契约
标题：任务分解机制与结构化输出。副标题：颗粒度止于可派发、可返回结果、可验证的技能步骤。
上半区绘制五阶段流程：目标结构化 → 上下文检查 → 注册技能匹配 → 构建依赖 DAG → 确定性契约校验。
各阶段对应短注：意图/约束/完成条件；有效性/缺失信息/预算；参数/前置条件/能力边界；先后关系/实际结果引用；无环/参数合法/最终验证。
下半区左侧三节点任务图：S1 解析会议室入口 → S2 导航至入口 → S3 验证到达并停止。S1到S2箭头标注 target_pose、frame_id、map_version；S1同时有依赖连到S3；S2到S3标注 final_pose、停止证据。
右侧输出契约清单：steps：步骤 ID、skill、args、deps；verification：最终验证节点 ID；执行层冻结计划与技能目录；执行层记录 revision / generation / execution_id。
底部强调：模型提出候选计划；执行层校验和调度；导航层处理路径与实时控制。
页脚：导航步骤为接口设计示意，尚未接入真实机器人。03 / 06

## 04 导航协作接口与验收要求
标题：基础导航案例：下层需要提供到什么程度。副标题：目标场景——已建图环境中，到东侧会议室门口并停止。
主体大表格五列“模块｜必须承担的工作｜关键数据｜更新方式｜验收要求”，六行：
导航执行｜路径规划、避障、局部恢复｜execution_id、status、failure_code｜状态变化事件｜成功/失败/取消可追溯
实时反馈｜发布位置、进度、阻塞状态｜pose、remaining_distance、timestamp｜周期反馈＋异常事件｜过期可识别，频率待联调
地图与定位｜维护地图、坐标变换和定位有效性｜map_version、frame_id、定位质量｜版本变化＋状态快照｜地图切换能触发引用重验
导航信息｜维护目标、路径及恢复次数｜goal_id、path_id、recovery_count｜目标/路径变化｜目标与执行身份一致
取消与停止｜取消控制器动作并确认停稳｜canceling/canceled、quiescent、evidence｜请求后持续查询｜收到取消不等于停止
独立验证｜检查目标误差与停止状态｜位置误差、朝向误差、来源证据｜动作结束后验证｜容差与阈值共同确定
底部画三节点箭头“下层权威状态 → 世界状态适配与有效性检查 → 分解层重规划输入”。
脚注：以上为最低闭环接口目标；反馈频率、超时和到达阈值尚待联合验收确定。04 / 06

## 05 反馈闭环泳道图
标题：执行反馈与任务重分解闭环。副标题：局部控制问题由下层恢复，任务策略变化才触发计划修订。
画主要泳道图，四条横向泳道从上到下“导航/感知”“执行编排”“上下文构建”“任务分解”。横向时间推进。
导航泳道从左到右“运行中：位姿与进度”→“遇阻：局部绕行”→“持续阻塞：失败原因、位置”。从持续阻塞箭头向下执行泳道“确认原执行已停止”；再向下上下文泳道“更新失败、位姿、地图版本”；再向下分解泳道“判断等待/换入口/补充感知”→“修订候选 DAG”；再向上执行泳道右侧“校验修订与资源，派发新步骤”；再向上导航泳道右侧“执行新目标”。所有箭头对应因果关系。
泳道下方并列三小框“普通进度：记录并展示，不反复重规划”“定位失效：停止或重定位后再规划”“地图变化：检查目标与路径引用”。
最下方醒目规则“结果未知或旧动作未确认停止：查询原 execution_id，保留资源，不直接重发。”
脚注：闭环目标设计；导航反馈适配及现场验收待完成。05 / 06
