# 分层 LA / 具身 Agent 框架：会议汇报提纲

会议日期：2026-09-15。建议按 10 分钟主讲、5 分钟讨论使用。本文中的“已验证”只指紧邻所列证据的范围；“建议指标”是下一轮验收口径，不是既有成果。

## 开场结论（约 40 秒）

我们做的是分层具身 Agent **框架**，而不是一个只会完成单个抓取或导航任务的模型。上层 LA 将开放目标解释为受约束的任务 DAG；中层确定性 Runtime 管理技能、资源、执行身份、恢复和证据；底层 ROS2/机器人控制器执行动作，独立安全链路负责物理保护。核心原则是：**模型只提出候选计划，不能直接取得机器人执行权；成功必须由实际执行结果和独立验证证明。**

## 一、整个框架怎样实现（约 2 分钟）

1. **目标与规划层**：`GoalContext` 保存原始目标及解释、约束、不确定性；`ContextBuilder` 组织目标、注册技能和任务状态。`ModelCaller` 调用显式配置的模型，`Planner` 校验返回的计划。当前语义分析有独立测试入口；常规 `agent` 提交路径仍直接以原始目标规划。
2. **确定性执行层**：`contracts.py` 校验计划 DAG、引用和技能契约；`Runtime` 决定何时派发依赖就绪的步骤，使用 SQLite 任务账本和资源事务；DBOS 保存持久工作流，worker 重启后查询原 execution ID。
3. **技能与机器人适配层**：技能注册表固定输入/输出 schema、资源、取消、重入和 verifier 属性。现有本地文件技能与 HTTP execute/query/cancel 协议已运行；ROS2/Unitree 真实动作适配器仍待接入。
4. **证据与运行观察层**：MCAP/rosbag2、资产哈希和时空元数据、模型原始响应、任务事件及只读 UI 留下可追溯记录。现有 ROS2 录制是诊断消息，不是机器人 RGB/点云流验收。
5. **独立安全层**：硬件急停、控制器限幅与控制权 fencing 属于必须与 Agent 分离的控制边界；控制端 fencing 和硬件安全联调尚未完成。

这是一条“上层秒至分钟规划—中层毫秒至秒协调—底层实时控制”的分层路径。当前单机、单 worker、单机器人优先，多机器人只预留 `robot_id`/资源命名空间。

## 二、首版任务拆分具体怎样实现（约 2.5 分钟）

**入口与输入。** `CLI plan` 只生成计划；`CLI agent` 调用 `Runtime.submit_goal`，在计划通过后提交任务；失败任务可通过 `Runtime.recover_plan` 有界重规划。Planner 输入是原始 goal、当前或任务冻结的技能目录，以及初次规划/重规划的上下文片段。

**模型候选。** `PlanningMethod` 要求 JSON：`{"steps":[...],"verification":"step_id"}`。每步声明注册技能、参数、依赖、可选重试/fallback；`{"$ref":"dependency_id.output_field"}` 只能引用直接依赖的实际输出。模型无法指定任意 endpoint，也不能修改注册技能权限。

**确定性双层门禁。** 一层验证模型响应和 JSON/DAG：1–256 步、ID 唯一、依赖存在且无环、引用合法、所有步骤通向最终验证节点。另一层在任务提交前核对实际注册技能、资源容量、重试安全性；最终 verification 必须对应注册的 verifier。无效计划拒绝并审计，不生成默认成功计划。

**执行与反馈。** 任务保存冻结 plan/catalog 和 revision/generation。Runtime 只派发依赖已成功且资源可得的步骤；远端执行 ID 在外部 IO 前入账。后续步骤使用上游真实 output。结果必须有匹配 ID、终态、quiescent、输出 schema、后置条件和来源证据。失败可按有界 retry/fallback 或整计划重规划处理；结果未知时不重发，也不释放资源。

**真实例子与边界。** 2026-09-07，`qwen3.8-max` 对 README 文件任务返回 `file.ingest → asset.verify` 两步 DAG，契约通过；记录中的 `plan_executed=false`。它证明模型规划接口和校验有效，**不证明任务已执行，更不证明机器人完成目标**。

## 三、路线图“阶段 1”做什么（约 1 分钟）

仓库的阶段 1 名称是“执行权威与恢复闭环”，与“首版任务拆分能力”不是同一个编号。当前已完成历史 plan/steps/catalog/revision/generation 快照。接下来依次做：

1. **控制端 fencing**：为控制域签发单调 token；execute/query/cancel/response 均带 token，控制端拒绝旧 token。仅靠本地 generation 不足以阻止旧进程继续影响物理机器人。
2. **补偿与人工接管契约**：定义何时补偿、补偿前观测、独立结果和人工处理终态。
3. **统一重试归属**：框架/行为层/驱动共享可追踪预算，不可重入动作只查询原 ID。
4. **故障矩阵**：进程退出、超时、迟到结果、取消竞争、控制换代、补偿失败、结果未知均有持久状态和证据。

阶段 1 退出后仍需阶段 2 的真实机器人技能纵向切片，才能声称机器人端到端完成。

## 六、会前可直接说的收尾（约 30 秒）

“我们已经有可运行的软件骨架和可审计的两步真实模型规划。现在最优先的不是让模型生成更长的文本，而是让每个计划步骤都有合法技能、唯一执行身份、资源控制权、可恢复状态和独立完成证据。本轮希望确认三件事：第一批真实机器人技能由谁提供；控制端能否落地 fencing 与停止回执；任务拆分评测集的任务族和验收口径如何定。”

## 可能被问到的问题

**问：这是不是多 Agent 系统？** 当前是分层具身 Agent 框架：模型规划、确定性编排和底层控制分工清晰。没有实现 Planner/Executor/Critic 多模型协商；不应称其为现有能力。

**问：为什么模型合法计划还不能直接执行？** 合法性只检查形式与注册能力；实际资源、控制权、环境状态、技能返回和最终目标都需要 Runtime/控制器/独立观测分别确认。

**问：阶段 1 完成后能演示机器人自主任务吗？** 阶段 1 的退出条件是执行权威和恢复的软件/协议闭环；真机端到端至少还需阶段 2 的适配器和实际 verifier。

**问：任务拆分达到什么水平？** 已有一次真实模型两步 DAG 接受证据和确定性校验、单机运行链路。尚无跨任务族长程规划成功率，不能给出实测百分比；建议先定义分母、数据集和独立完成证据。
