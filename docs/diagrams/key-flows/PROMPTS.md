## 01-goal-analysis
标题：目标语义分析与信息缺口分流
顶端“原始目标 + 会话输入”→“goal_analysis 模型调用”→“JSON 与 GoalContext 契约校验”。
校验失败向右“拒绝并保存审计记录”；校验通过向下“保存语义档案”→判断菱形“需要用户澄清？”
菱形下方小注“存在 clarification_requests，或有 missing_information 且无 grounding_requests”。
是分支向左“goal_clarification 生成问题”→“校验并返回 1–3 个问题”→“用户补充后重新分析”，回到首节点。问题校验失败连“拒绝并保存审计记录”。
否分支向右判断“存在环境查询需求？”；是→“返回 grounding_requests”→虚线“下层感知 / 世界状态补充”；否→“返回就绪 GoalContext”。
底部说明“当前：语义分析与澄清入口已实现；环境查询请求不等于已执行感知。”
来源小字“依据：goal_analysis.py”。

## 02-context
标题：上下文构建与调用前审计
上方三个实线输入框“GoalContext”“注册 / 冻结技能目录”“任务账本（有 task_id 时）”汇聚“ContextBuilder”。任务账本先经过“核对 revision / generation”，失败分支“拒绝陈旧上下文”。
ContextBuilder下方“ContextBundle：目标、能力、任务关系图”→“预算分配与权限分层渲染”→“prepared messages + allocation”→“持久化 ContextManifest”→“发送模型请求”。
预算与渲染节点旁注“必需片段、优先级、纳入/丢弃、Token 估算”。
Manifest旁注“request_id、phase、来源片段、预算、渲染版本”。
侧边三个虚线框“Session Provider”“Memory Provider”“World State Provider”通过虚线指向Builder，明确标“待接入”。
底部说明“Manifest 在发送前保存；模型调用失败仍可追溯本次上下文。”
来源小字“依据：context_builder.py / model_call.py / planner.py”。

## 03-planning
标题：任务 DAG 生成、校验与提交边界
起点“目标 + 上下文 + 注册技能目录”→“模型生成候选 JSON”→“解析 steps / verification”→“DAG 与技能契约校验”→“最终节点为注册 verifier？”。
契约节点旁小字“步骤 ID、依赖无环、参数引用、输入输出约束”。
JSON解析和契约校验及verifier判断的失败路径汇入右侧“拒绝候选计划 + 保存错误与原文”。
verifier通过向下“保存 validated 计划与响应 ID”。
然后分成两条明确不同入口路径：左“plan / 独立工作台”→“返回计划，不执行”；右“agent / Runtime.submit_goal”→“提交校验与冻结计划”→“任务账本与依赖调度”。
底部说明“已通过计划契约，不能据此宣称机器人目标完成。”
来源“依据：planner.py / runtime.py”。

## 04-runtime-feedback
标题：执行结果如何进入重规划闭环
画左右闭环。左上“依赖就绪 + 资源可用”→“持久化 execution_id”→“派发 / 查询原执行”→判断“执行结果？”
三个带标签分支：running→“更新状态，继续查询”回到查询；unknown→“保留资源，仅查询原 ID”回到查询；终态→“校验停止证据与结果契约”。
终态校验成功后判断“成功或失败？”成功→“保存实际输出”→“推进依赖 / 最终验证”；失败→“满足自动重规划条件？”。
重规划判断旁小字“失败状态、无活动执行、次数预算未耗尽”；否→“保持失败，等待处理”；是→“失败与历史进入上下文”→“模型生成并校验修订计划”→“复核 generation 与用户控制”→“保存修订与历史”回到“依赖就绪 + 资源可用”。
在停止证据校验框侧注“证据无效不得按可信终态释放资源”。
底部说明“用户取消不能被迟到重规划覆盖；此图聚焦重规划分支。”
来源“依据：runtime.py / planner.py / 技能协议”。

## 05-navigation
标题：导航协作的数据流与维护责任
这是一张目标接口图，所有跨模块箭头均为虚线，图例标“虚线：待接入目标接口”。
三列：左“任务分解层”，中上下“执行编排”“世界状态适配”，右上下“导航模块”“地图 / 定位模块”。
任务分解层到执行编排箭头“技能步骤、依赖、目标引用”；执行编排到导航箭头“execution_id、目标位姿、取消请求”。
导航到执行编排回箭头“运行状态、失败原因、终态与停止证据”，两方向箭头错开。
地图定位到世界状态适配箭头“地图版本、TF、位姿、定位质量”；导航到世界状态适配箭头“目标 / 路径版本、剩余距离、时间戳”。
世界状态适配到任务分解层箭头“有效状态快照 + 失效事件”；执行编排到任务分解层箭头“已完成事实 + 失败与证据”。
每个模块内短注：导航“路径规划 / 避障 / 局部恢复”；地图定位“地图维护 / 坐标一致性”；世界状态“时效检查 / 版本关联”。
底部列三个联合验收项“反馈频率与过期阈值”“到达误差与停止验证”“地图切换与目标重验”。
边界说明“目标设计：当前框架尚无已验收的真实导航适配器。”
