# 上下文资产版本绑定

`session.attach-assets` 保持原有输入接口，但现在将真实资产字节及其完整登记记录绑定到会话。此前只保存 asset_ids，规划后修改资产元数据可能没有在提交边界被发现；现在绑定显式保存记录哈希，并在使用边界复核。

## 契约

`context_models.AssetBinding` 是 v1 的已保存资产引用：schema_version、asset_id、robot_id、record_hash、sha256、size。字段集合固定，未知字段/版本、布尔型版本或大小、非规范 SHA256 均拒绝。绑定的 robot_id 是本会话使用范围；资产仍须属于该机器人，或为既有规则允许的无 robot_id 资产。动作原有资产读取权限继续生效。

record_hash 覆盖实际资产登记记录，包括元数据和存储路径；sha256 与 size 指向实际读取的归档字节。它不证明文件描述的语义真实性，也不是物理物体 ID、实时位姿或 WorldState。实体消歧、TF/时钟/地图有效性及机器人完成条件仍需独立实现。

## 生命周期

| 边界 | 行为 | 不满足时 |
|---|---|---|
| 附加资产 | 检查主体权限、会话 robot 范围及实际字节，在事务内保存 asset_ids 与 asset_bindings | 整次操作拒绝，会话不部分更新 |
| 构造模型上下文 | 检查附件与绑定一一对应，复核记录哈希和字节 | 必需证据不可用，拒绝模型准备，不静默丢弃 |
| 模型返回后发布草稿 | 再核对当前会话版本和绑定资产 | 保留真实模型记录，拒绝发布过期草稿 |
| 提交草稿 | 读取被绑定的规划快照并复核其中的资产 | 不接受执行命令 |
| worker 接受命令 | 再读快照及资产 | 持久记录 command_rejected，不创建任务或派发 |
| 每次新技能派发 | 在派发意图事务内复核已接受快照与绑定资产，随后才申请资源并写派发记录 | 记录 context_rejected；该步骤失败，不派发、不申请资源 |
| 自动恢复 | 沿用原快照绑定，在模型准备与返回后复核 | 拒绝恢复，不凭最新资产记录改写原计划依据 |

`AssetProvider` 继续产生 data 权限的 asset-evidence 片段，元数据含 asset_bindings，scope 为 stored_asset_bytes_and_bound_record。Bundle/Manifest 与规划快照因此保存精确引用。没有改变 Bundle v1 的顶层字段格式，也不回填历史模型记录。

查询或取消已有 execution 不经过新增派发检查；故障处理继续遵循原有停止与资源协议。文件系统不受 SQLite 事务锁保护，绑定检查只能证明检查时的字节，技能仍须在实际读取/执行和后置条件上核验。绑定归档字节也不意味着任意原始文件路径随后不会改变。

## 旧记录与恢复方式

历史会话、Bundle 和快照仍可只读查看。有非空 asset_ids 却没有版本绑定的旧上下文不能用于新的模型准备或技能派发；错误要求重新附加资产，不自动用当前元数据补出旧版本。操作者应重新调用 session.attach-assets（传原有 ID 或重新选择），重新分析并生成/提交新草稿。重新附加会提升会话 revision 并清除旧分析；原快照保持不变。空附件会话不要求新增绑定字段。

## 实际验证

[asset-binding-live.json](validation/asset-binding-live.json) 保存本环境 qwen3.7-plus 的 4 条真实响应（1 次目标分析、3 次规划），实际请求、原始响应与 Bundle 哈希；每条输入均准确重建，模型从已绑定资产上下文取出真实 asset_id 和预期 SHA256。

验证规划后修改元数据阻止提交、排队期间修改元数据使独立进程拒绝命令、命令接受后损坏归档字节阻止技能派发及自动恢复；恢复原记录与字节后，再次真实规划由独立 worker 完成 asset.verify-set，实际资产 ID、大小和哈希与预期一致。账本只有一次真实技能执行，另有一个被拒命令和一个未派发即失败的任务，失败证据保留。

专项 1 项通过，相关实际文件/SQLite/动作回归 37 项通过。测试没有 mock、仿真或替代模型响应；使用环境模型与密钥配置，密钥不写入报告。该结果不代表机器人实体绑定或通用完成条件已完成。
