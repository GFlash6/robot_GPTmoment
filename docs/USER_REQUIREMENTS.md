# 用户需求与当前阶段（对话证据）

## 已确认的用户要求

- 建设机器人 Agent 框架，核心是长程任务分解、子任务编排、原子技能调用、失败 fallback 与打断。
- 第一版完整管理单台机器人的多任务与多资源，同时预留多机器人接口。
- RGB、深度、点云以及点云/占据/体素地图需要保存、分类和记忆管理。
- 聚焦框架，不深入某一个探索场景的下层算法。
- AI 调用以实际响应为标准，技能调用以实际返回为标准，不以 call 成功判成功；不得使用占位、模拟、假设结果。
- 大规模修改之前先广泛调研开源仓库，尽最大可能利用现有资源。
- 使用 momo 维护整个项目，并持续维护具体模块待完善问题。

## 调研阶段的历史状态（当前实现见 docs/VALIDATION.md）

- 项目工作目录为当前仓库中的 robot_agent_framework；这是已创建的工作目录，不代表技术选型已确认。
- 只有文档、pyproject.toml 和契约测试；尚不存在 robot_agent 生产包。
- 首次 unittest 执行 6 项：1 failure、5 import errors；原因是生产模块尚未实现。不能称测试通过。
- 用户要求调研优先后，框架实现暂停；既有 ARCHITECTURE.md 和 IMPLEMENTATION_PLAN.md 属于待调研修订的初稿。
- 本轮无 AI 实际任务规划响应、无机器人技能实际执行验收。

## 不应混淆

工作流重放不代表机器人副作用可重放；LLM interrupt 不代表控制器已经停止；地图资产不等于语义记忆。
