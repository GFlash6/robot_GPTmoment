# 解耦流程可视化 UI 设计

状态：已实现独立只读 UI，并通过真实账本、构建和浏览器验证。用户已要求直接实施，不再使用 superpowers。来源：用户要求“做一个解耦的ui界面，可视化各个流程”。本模块归属于已注册的单一机器人框架项目，不另建 Momo Project。

## 推荐方案

2026-09-07 增补：用户授权添加可视化真实问答。模型记录页新增测试表单、实际回答和历史，复用现有界面风格；单独启动模型测试网关提供真实 API 调用。任务账本仍只读，顶部文案明确为「账本只读」。详见 [模型测试 UI](MODEL_TEST_UI.md)。

独立 React + TypeScript + Vite 前端，React Flow 展示任务 DAG；独立只读查询服务把现有运行账本转换为版本化 HTTP DTO。UI、查询服务和 worker 分别启动与停止。第一版只读；用户此次要求可视化，没有明确要求通过 UI 控制机器人。后续控制功能可以独立加 command API，复用已实现的 Runtime 控制语义。

另两种路线：直接在 Python 内渲染页面，依赖少但前后端边界较弱；把整个运行台做进 Momo Web，能共享图组件但会混淆项目管理图与真实运行态。选择独立运行台，Momo 继续维护需求、实现与验证证据。

React Flow 复用缩放、平移、选择、自定义节点与适配视野能力，禁用连接编辑；不自行重写图交互引擎。[官方接口](https://reactflow.dev/api-reference/react-flow)。Vite 输出独立静态资源，可由单独静态服务器或查询服务提供。[构建部署说明](https://vite.dev/guide/static-deploy.html)。实际依赖已安装并锁定于 ui/package-lock.json。

## 真实状态规则

- 无任务、无数据或无模型记录时展示明确空状态，不填充示例数据。
- 使用账本状态，不在浏览器推导技能成功；accepted、running、unknown、pausing/canceling 与终态分别呈现。停止确认单独展示。
- “步骤完成数/总步骤数”仅是节点计数，不伪装成时间进度或目标完成概率。
- fallback 未使用时是计划中的候选分支；只有执行记录证明使用过，才显示实际执行轨迹。重试来源于真实执行记录，不复制动画节点制造次数。
- events 并不覆盖所有瞬时状态变化，因此时间线只呈现已记录事件；没有起止时间时不计算虚构耗时。
- 计划修订使用保存的 plan_history；历史中未保存的执行信息标明不可用。没有模型记录引用时不靠相同 goal 猜测关联。
- 资产列表列出已登记的哈希；只有后端实际读取校验后才显示“已校验”。UI 第一版不把点云/地图元数据冒充三维渲染，也不补造相机画面。
- 连接失败保留上次数据显示为过期，显示最后成功观测时间；不能继续显示为实时。UI 连接正常不等于 worker 或机器人在线，当前内核没有可据以判断的 worker 心跳。

## 解耦边界

前端只依赖 `/api/v1` 数据契约，不访问文件系统、SQLite、DBOS 或 ROS2。查询服务不导入 Runtime、DBOS 或 Skills，不派发任务，也不轮询真实机器人服务。

查询适配器使用 SQLite URI mode=ro 和 query_only；每次相关查询在一个只读事务中读取，不能实例化会创建数据库/迁移表结构的现有 Store。账本不存在返回明确“未连接账本”，不新建空库。替换持久化后端只更换这个查询适配器，前端保持 DTO 不变。

查询进程默认仅绑定 loopback。浏览器访问地址与 API 根由配置提供。开发时使用 Vite proxy，构建后的静态资源可单独部署；仅允许明确配置的跨域来源。第一版不提供远程公网认证部署，也不把凭证环境变量或完整 model_config 暴露给前端。

每两秒获取一次查询快照/当前任务详情；事件按 seq 游标增量加载。轮询不触发 worker，不给内核加 UI 回调。以后可在保持 DTO 不变的前提下增设推送传输。

## API 契约

| GET 路径 | 返回范围 |
|---|---|
| /api/v1/overview | API 版本、观测时间、账本可用状态、真实任务计数、最新事件 seq |
| /api/v1/tasks | 有界分页任务摘要，支持 robot_id/status 筛选 |
| /api/v1/tasks/{id} | 当前计划、步骤、该任务的执行、待处理控制和计划历史 |
| /api/v1/tasks/{id}/events?after_seq= | 按 seq 排序的有界事件增量 |
| /api/v1/resources | 容量、占用量、实际 owner 与可解析任务关联 |
| /api/v1/assets | 分页元数据，支持 kind/robot_id/frame/time/version |
| /api/v1/memories | 分页条目及来源资产 ID |
| /api/v1/models | 分页响应元数据；原始响应按 ID 单独读取 |

数据响应包含 observed_at、api_version；列表包含分页信息。错误区分账本不存在、数据库忙、数据结构不支持、记录不存在。未知字段在受控详情中显示原始 JSON，不能使整个页面崩溃。模型正文、事件错误和资产标签以文本渲染，不执行 HTML。模型大响应与大量历史事件按需加载。

## 文件边界与启动

- `ui/`：前端独立 package.json、锁文件、页面、API 客户端、样式和构建配置。
- `robot_agent_observer/`：只读账本适配器、DTO、HTTP 服务入口。与 robot_agent 核心包平级，导入不启动 worker。
- `tests/test_observer.py`：真实账本查询与 API 检查。
- `docs/UI_API.md` 和 README：接口、前端构建、独立启动和空状态说明。

启动命令为 robot-agent-observer；运行账本路径显式提供，实际命令见 README。

## 验收

1. 通过现有真实文件技能生成任务记录，UI 展示实际 DAG、输出和证据；不添加模拟后端。
2. 运行真实失败/fallback、本地分块复制取消流程，核对图状态、时间线与资源账本一致。
3. 断开查询服务后显示过期/离线；停止 UI 不影响正在执行的任务。
4. 只读查询不创建缺失账本，不改写现有 task、event、lease；UI 无执行控制接口。
5. 对实际数据库执行 API 集成测试，前端完成类型检查、构建和浏览器交互检查。没有可用浏览器自动化时明确记录验证缺口。
6. 更新 Momo UI 工作项、接口决策、验证证据和仍未实现的三维数据预览等模块问题。

交付范围为独立、只读、使用实际账本的可视化运行台，验证与限制见 UI_VALIDATION.md。
