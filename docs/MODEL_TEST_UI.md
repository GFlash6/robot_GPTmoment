# 可视化真实问答测试

在项目根目录执行（服务进程需继承已设置的 `API_KEY` 环境变量）：

```bash
cd ui
npm run build
cd ..
.venv/bin/python -m robot_agent_observer.model_test --root .runtime/model-validation --model-config .runtime/model-config.json --static ui/dist
```

打开 http://127.0.0.1:8767，选择「模型记录」→「真实问答测试」。输入问题，按需填写预期答案，点击「发送测试」。URL 和模型来自显式配置文件，模型固定为 `qwen3.8-max`；密钥通过配置的 `token_env` 在服务端读取。

## 语义与上下文真实链路

同一页面顶部提供「语义 → 上下文 → 规划」测试台。它不接受浏览器伪造的语义分析结果，也不生成模拟成功数据：

1. 输入原始目标并点击「调用真实模型分析」。服务端通过 `GoalAnalyzer` 发起真实模型调用，严格校验 JSON，并将响应写入 `model_responses`。
2. 如果模型提出追问，可填写补充说明并重新进行一次真实分析；回答不是必需的。跳过时，未确认的信息仍保留在 `GoalContext` 中，可继续生成上下文并尝试规划。
3. 点击「从已验证分析生成上下文」。服务端按分析审计 ID 重新读取已验证结果，通过 `ContextBuilder` 读取当前 root 中的真实技能目录，再用规划调用边界生成实际 messages 和预算清单。此步骤不调用模型。
4. 点击「使用该上下文真实规划」。服务端通过 `Planner` 再次调用真实模型，并校验步骤 DAG、注册技能名称和最终 verifier；通过后显示计划、模型审计 ID 和 ContextManifest ID。此操作不会提交或执行机器人任务。

例如输入 `到厨房去找热水壶`。如果当前 root 没有导航、视觉搜索和目标验证技能，真实规划应被拒绝；页面不会用样例技能或假计划填补能力缺口。若需要测试可执行规划，应先把真实技能注册到启动参数 `--root` 指向的账本。

每次发送调用真实 API 并消耗额度。回答、耗时、返回模型、HTTP 状态和响应 ID 显示在页面中。预期答案不会发送给模型，只在本地按去除首尾空白后的全文匹配；不填写则显示「未判定正确性」。请求成功不等于回答正确，也不代表机器人任务完成。

历史保存在所选 root 的 `model-tests.sqlite`，包含问题和回答，请避免输入敏感内容。页面重载后可以查看最近 50 条。网络中断时先刷新历史确认结果；不会自动重试。进程中断留下的「待确认」记录没有完成证据。

测试网关仅监听 loopback，独立启动；原 `robot_agent_observer.server` 仍只接受 GET。开发模式 `/model-test` 代理到 8767，原账本 API 仍代理到 8765。构建后的完整测试界面直接由 8767 提供。

真实浏览器验收（需先启动网关）：

```bash
cd ui

```
