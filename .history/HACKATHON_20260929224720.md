# GPTmoment for robot：面向多场景任务的机器人技能编排

## 一句话定位

GPTmoment for robot 以机器人通用技能编排为核心，将导航、感知、操作、交互与设备调用统一表达为 Skill，围绕用户目标组合成适配不同场景的任务流程。系统采用本地优先、可迁移的部署方式，DGX Spark、GPU 工作站与其他边缘节点均可作为模型与任务运行环境。

## 产品主线

任务需求决定技能如何组合：递送物品需要查询、导航、识别、抓取与交接；接待访客需要对话、地点查询、引导与到达确认；工位协作需要定位、操作和状态复核。技能目录随设备能力扩展，任务流程遵循技能前置条件、资源约束与完成标准。

展示时先讲通用技能体系与跨场景组合，再以已提供的图像巡检入口展示目标、技能执行、现场证据与验证器之间的协作。

## 本地部署优势

- 视觉语言模型在现场本地运行，图像不离开部署环境。
- 断开公网后，任务规划、视觉判断和证据验证仍能形成闭环。
- 模型接口、机器人 Skill 接口与运行主机解耦，迁移时无需改 Agent 流程。
- 页面直接显示加速器、模型端点性质和机器人连接状态，不把非本地模型包装成本地部署。

## DGX Spark 在比赛中的角色

DGX Spark 是推荐的高性能参考部署：统一内存和本地 GPU 推理适合在一个现场节点同时承载 VLM、规划和验证。它证明本地部署上限，但不是 GPTmoment for robot 的运行前提。

## 在 DGX Spark 上启动

先在任意本地节点启动 OpenAI-compatible VLM。使用 DGX Spark 时可以采用 NVIDIA 官方 vLLM Playbook，然后：

```bash
chmod +x start_gptmoment.sh
MODEL_ENDPOINT=http://127.0.0.1:8000/v1/chat/completions \
MODEL_NAME=Qwen/Qwen2.5-VL-7B-Instruct \
./start_gptmoment.sh
```

浏览器访问 `http://<spark-ip>:3030`。需要真实导航时再设置：

```bash
export ROBOT_SKILL_URL=http://<robot-adapter>:9000/skills/run
```

该同步端点接收：

```json
{"execution_id":"...:navigate","skill":"robot.navigate","args":{"destination":"A 区"}}
```

成功响应必须包含真实证据：

```json
{"status":"succeeded","evidence":[{"source":"controller-log-or-sensor"}]}
```

## 三分钟产品展示脚本

1. 用物品递送或访客接待说明产品目标：围绕任务自由组合机器人技能。
2. 展示技能类别与通用架构，说明导航、操作、感知和交互都通过能力契约接入。
3. 切入图像巡检工作台，展示计算节点与模型配置，输入“检查当前区域的消防通道是否被物品占用”。
4. 上传现场画面并执行，解释此任务所用的导航、观察、分析和验证四项 Skill。
5. 展示结论、置信度和原始执行记录中的证据路径，说明不同任务应有不同完成标准。
6. 回到通用编排立意：通过新技能与设备适配器拓展到递送、操作和交互任务，通过配置迁移到不同现场计算节点。

## 行业扩展蓝图

GPTmoment for robot 的 Agent Core、Skill 协议与证据协议保持稳定，不同行业通过 Skill Pack 接入：

- 制造：工件上下料、物料补给、协作操作与质量复核。
- 能源：设备检查、工具递送、授权操作与状态复核。
- 物流：物品拣选、搬运、配送、交接与盘点。
- 园区：访客接待、引导、物品递送与设施服务。

当前图像巡检入口提供一条可运行任务链。通用技能编排的扩展围绕操作、交互、设备调用及依赖、并行、条件分支等任务表达展开，具体可执行能力由接入设备和运行器提供。
